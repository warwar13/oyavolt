## Screen-off recording reliability (2026-10-20)

- Investigated the connected Poco: foreground monitoring was alive but raw data contained repeated 30-second to multi-minute gaps, no CPU wake lock existed, and Android optimization was enabled. A foreground service and coroutine delay alone do not prevent CPU suspension.
- Added a per-monitor partial CPU wake lease: two-minute automatic timeout, renewed after one minute only on BLE-loop progress; explicit Stop, destruction, cancellation, and failure release it. Bluetooth-off releases it and waits for a system enable broadcast instead of polling every two seconds. Permission errors stop the loop rather than retrying with the CPU held awake.
- Settings now shows the actual Android battery-optimization exemption, a user-initiated system allowance button, Poco setup guidance, and the last successful database-save timestamp with a stale-write warning. The allowance action targets Android Settings first because MIUI redirects the generic action. The foreground status notification, BMS warnings, SOC reminders, telemetry allowlist, database, and gap-safe integration remain intact.
- All 130 unit tests, `lintDebug`, and `assembleDebug` pass. Final APK installed on Poco with existing data retained. A 185-second screen-off run saved 35 rows at 5.172–5.447 second spacing with no gap markers, beyond the initial lock timeout. In a second run, the system event log verified 71.061 seconds of deep Doze before an existing alarm exited idle: 14 rows, maximum spacing 5.359 seconds, no gaps. Both tests used USB plus simulated unplug; neither is an overnight drain measurement. Reports: `docs/background-recording-verification.json` and `docs/background-doze-verification.json`.
- Bluetooth-off/on device check verified actual OFF state, lock release while off, lock reacquisition and foreground service recovery after enabling. The Poco's `svc bluetooth` helper exits 137 despite applying the changes; actual adapter state and lock ownership were checked independently (`docs/background-bluetooth-verification.json`). Lease Stop/late-callback behavior is unit-tested; a separate device Stop-release assertion was not completed after device UI tooling became unreliable. Android CLI layout inspection crashes on this API level; this is a tool crash, not an OyaVolt crash.
- Left the foreground monitor active with Android exemption enabled, Bluetooth on, and fresh database writes (last five rows approximately 5.2 seconds apart, no gap markers). Restored battery simulation, forced-idle mode, and the original 30-second screen timeout; display left off. Poco Autostart/No restrictions and unplugged overnight/24-hour coverage and added drain still need verification. Keeping five-second polling awake can materially increase power use; no low-drain guarantee is claimed.
